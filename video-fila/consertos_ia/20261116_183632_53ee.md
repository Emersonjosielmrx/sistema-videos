## 1. CAUSA

O timeout dinâmico do Whisper está **insuficiente para vídeos curtos quando a CPU está carregada**.

**Prova (arquivo:linha + log):**

**anime_fetch.py:452-455:**
```python
if max_seconds <= 600:
    duracao_real = max(60, max_seconds - 60)
    whisper_timeout = max(900, int(duracao_real * 5))
```

**Log _parceiro_20261116.log (linhas 949-950, 18:25:52):**
- Vídeo `gMvJdUybB6E` (duração real: **134.13s = 2min 14s**)
- `max_seconds` passado: **194s** (134 + 60 do anime_auto.py:280)
- Cálculo: `duracao_real = 134s`, `5x = 670s`, `max(900, 670) = 900s`
- **Timeout usado: 900s (15min)**
- **Tentativa 1 (tiny):** timeout às 18:10:26 (após 900s)
- **Tentativa 2 (base):** timeout às 18:25:52 (após 900s)
- **Total:** >30min para processar 2min de vídeo (ambas tentativas estouraram)

**Problema:** O **mínimo de 900s** prevalece e é insuficiente. Com CPU carregada, o Whisper está levando **mais de 15 minutos** para cada tentativa em vídeos de 2 minutos.

Hoje (16/11) houve **8 timeouts do Whisper** (00:55, 10:20, 10:36, 11:02, 11:18, 11:37, 18:10, 18:25) — todos com timeout fixo de 900s.

## 2. PLANO

**Aumentar o mínimo do timeout de 900s para 1800s (30min)** para vídeos curtos, garantindo margem suficiente quando a CPU está carregada.

**Mudanças:**

**Arquivo: `D:\recapd-ambientes\producao\bin\anime_fetch.py`**

**Linha 455 — DE:**
```python
whisper_timeout = max(900, int(duracao_real * 5))
```

**PARA:**
```python
whisper_timeout = max(1800, int(duracao_real * 5))
```

**Justificativa:** 
- Vídeos de 2-3min precisam de até 2000s (~33min) com CPU carregada
- 1800s (30min) dá margem para processamento pesado sem explodir o timeout
- Mantém o multiplicador 5x para vídeos maiores (>6min já terão 5x > 1800s)

**Teste após mudança:**
```bash
# Simular o cálculo para o vídeo que falhou
python -c "dur=134; timeout=max(1800, int(dur*5)); print(f'Duração {dur}s -> timeout {timeout}s ({timeout/60:.1f}min)')"
```

## 3. RISCO

**Riscos:**
1. **Timeout muito alto pode travar o sistema por 30min** se o Whisper realmente falhar (não apenas CPU lenta)
2. **Processo pode ficar pendurado** se houver deadlock no Whisper

**Como desfazer:**
```bash
# Reverter para o valor anterior (900s)
# Editar anime_fetch.py:455 e trocar 1800 de volta para 900
```

**Mitigação:**
- O timeout de 1800s (30min) é razoável: logs mostram que vídeos de 2min levaram >30min total com CPU carregada
- O código já tem fallback: tenta `tiny` primeiro, depois `base` — se ambos falharem, pula o vídeo
- O sistema continua funcionando: outros vídeos entram na fila enquanto aguarda
