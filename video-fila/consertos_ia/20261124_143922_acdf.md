## 2. PLANO

**Arquivo:** `D:\recapd-ambientes\producao\bin\anime_auto.py`

**Mudança (linhas 1017, 1022, 1045):**

**SAI:**
```python
r = subprocess.run(cmd, env=env)
```

**ENTRA:**
```python
r = subprocess.run(cmd, env=env, timeout=14400)  # 4h = worker timeout (linha 950)
```

**Por que 14400s (4 horas):**
- Linha 950 já usa `timeout=14400` para workers remotos
- Shorts normais saem em 5-15 min; 4h cobre até casos extremos de clone pesado
- Evita travar por 2h44min como aconteceu hoje

**Depois:** Rodar teste com um short que use voz clonada kokoro (se o modelo continuar faltando, vai dar timeout em 4h em vez de travar infinito).

**NOTA:** O problema do modelo kokoro faltando é **separado** e precisa ser resolvido (restaurar de backup ou baixar), mas **não é parte deste conserto** (que é só adicionar timeout).

---

## 3. RISCO

**Risco baixo:**
- Adicionar timeout de 4h não quebra nada (workers remotos já usam isso)
- Se um short realmente precisar de mais de 4h, vai dar timeout em vez de travar — erro visível é melhor que trava silenciosa

**Como desfazer:**
- Remover o parâmetro `timeout=14400` das 3 linhas (volta ao comportamento anterior)

**Risco separado (modelo kokoro):**
- Voz julius (e outras vozes kokoro) continuam falhando até restaurar `D:\hipercool-materiais\models\kokoro\kokoro-v1.0.onnx`
- Isso NÃO é risco deste conserto — é o problema pré-existente que o timeout vai expor rapidamente em vez de travar
